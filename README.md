# ChatGrab — сборщик сообщений Telegram-чатов

Desktop-приложение для Windows, которое подключается к нескольким Telegram-чатам
(например, чатам-биржам, где поставщики и производители публикуют запросы и
предложения), собирает из них всю историю и новые сообщения по мере поступления,
и выгружает собранное в CSV / JSONL / Markdown. Дальнейший разбор — какие товары
запрашивают, в каких объёмах, по какой цене — делает Claude в обычном чате при
работе с выгруженным файлом. Само приложение аналитику не делает: только надёжно
собирает и структурирует сырые данные.

## Возможности

- Один вход в Telegram на всё приложение (номер телефона → код → пароль
  двухэтапной проверки при необходимости).
- Список отслеживаемых чатов: добавление по ссылке/username или выбором из
  диалогов аккаунта, включение/выключение сбора по чату, удаление из списка
  с выбором «оставить данные» или «удалить вместе с чатом».
- Загрузка истории каждого чата с самого начала или от заданной даты, с
  докачкой при перезапуске — сбор продолжается с последнего собранного
  сообщения. Чаты грузятся по одному, а не параллельно — это специально:
  ограничение скорости у Telegram общее на аккаунт, и последовательная
  очередь реже вызывает `FloodWait`, чем параллельная загрузка.
- Прослушивание всех включённых чатов в реальном времени одновременно —
  это работает через push-события, а не опрос, поэтому общего лимита
  не касается и не требует очереди.
- Локальная база SQLite (один файл), дедупликация по паре (чат, id
  сообщения), обновление записи при редактировании исходного сообщения.
- Скачивание фото из сообщений (включено по умолчанию, можно выключить) —
  `photos/<chat_id>/<message_id>.jpg`. Видео, документы и голосовые не
  скачиваются — только тип и подпись.
- Экспорт: выбор чатов (объединить или по отдельности), формат CSV / JSONL /
  Markdown-дайджест по дням, диапазон дат, три режима разбивки на файлы —
  «по размеру для Claude» (лимит токенов настраивается, по умолчанию 180 000,
  токены считаются приближённо как символы/4 — без лишней зависимости),
  «по месяцам» или «одним куском». Инкрементальный экспорт («только новое
  с прошлой выгрузки»), журнал выгрузок с повтором прошлых, пресеты,
  архив фото рядом с выгрузкой, редактируемая шапка Markdown-дайджеста.
- Экран **Обзор**: сводка по базе и плитки по каждому чату с графиком
  активности за 16 суток и предупреждениями (сбор выключен, чат в очереди,
  давно нет сообщений).
- Экран **Поиск в собранном**: полнотекстовый поиск (SQLite FTS5) с
  фильтрами по чату, автору, датам, фото/пересылкам/ответам — чтобы
  проверять качество сбора, не открывая Telegram. Найденное можно сразу
  отправить на экспорт.
- Правила игнора (по автору или стоп-слову, глобально или по чату) —
  помечают сообщения скрытыми, не удаляя их; можно применить задним
  числом к уже собранному. Список авторов по чату — чтобы быстро находить
  спам.
- Адаптивная пауза между запросами истории (растёт после `FloodWait`,
  плавно снижается на успешной серии), расписание окна загрузки истории,
  проверка целостности с «залатать пропуски», устойчивость к обрыву сети.
- Резервные копии базы по расписанию, сжатие базы (VACUUM), быстрый доступ
  к папкам базы и фото.

## Установка

### Вариант 1 — готовый файл (рекомендуется)

Каждый пуш в этот репозиторий собирает portable `ChatGrab.exe` в GitHub
Actions (`.github/workflows/build-windows.yml`, раннер `windows-latest`,
PyInstaller). Скачайте его со вкладки **Actions → последний прогон →
Artifacts → ChatGrab-windows**, либо, если в репозитории есть релиз с тегом
`vX.Y.Z`, — со страницы **Releases**.

`ChatGrab.exe` не требует установки — запускается двойным щелчком. Все
данные (база, фото, выгрузки, файл входа, `config.json`) приложение хранит
в папке рядом с собой, поэтому всю папку с `.exe` можно свободно переносить
на другой компьютер или флешку вместе с уже собранными данными.

### Вариант 2 — запуск из исходников

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Требуется Python 3.11+.

### Вариант 3 — собрать .exe самостоятельно

На Windows, после `pip install -r requirements.txt pyinstaller`:

```
pyinstaller packaging/chatgrab.spec --noconfirm --clean
```

Готовый файл появится в `dist\ChatGrab.exe`.

## Первый запуск

1. **Ключи доступа.** На <https://my.telegram.org> → «API development tools»
   создайте приложение и получите `api_id` и `api_hash`. Внесите их на
   экране **Настройки → Доступ к Telegram** и нажмите «Сохранить».
2. **Отдельный аккаунт.** Файл входа даёт полный доступ к аккаунту Telegram
   — для сбора рекомендуется завести отдельный номер, не основной личный,
   а не использовать основной аккаунт.
3. **Вход.** Экран **Подключение** → введите номер телефона → код из
   Telegram → пароль двухэтапной проверки, если он включён в аккаунте.
   Вход выполняется один раз на всё приложение.
4. **Добавьте чаты.** Экран **Чаты → Добавить чат** — ссылкой/username или
   выбором из своих диалогов. По умолчанию каждый чат грузит всю историю
   с начала; глубину («вся история» или «с такой-то даты») можно задать
   отдельно для каждого чата при добавлении.
5. **Дождитесь сбора** (экран **Сбор данных** или **Обзор**) — чаты
   грузятся по очереди, это нормально при нескольких чатах сразу.
6. **Экспортируйте** — экран **Экспорт**: выберите чаты, формат и период,
   нажмите «Экспортировать». Получившийся файл можно приложить прямо в
   чат с Claude для разбора запросов, объёмов и цен.

## Где что лежит

Рядом с `ChatGrab.exe` (или, при запуске из исходников, в корне проекта)
приложение создаёт:

```
config.json          — api_id/api_hash и пути (не в коде, отдельно)
data/chatgrab.db      — база данных (сообщения, чаты, настройки, пресеты)
data/photos/<id>/…    — скачанные фото, по чатам
data/exports/          — выгруженные файлы по умолчанию
data/session/           — файл входа в Telegram-аккаунт
data/backups/            — резервные копии базы
```

Файл входа (`data/session/worker.session`) и `config.json` — храните
локально, никогда не пересылайте и не кладите в выгрузки: они дают полный
доступ к аккаунту Telegram.

## Ограничения

Приложение не извлекает товары, объёмы и цены из текста и не строит
сводки — только надёжно собирает и выгружает сырые данные. Разбор смысла
сообщений остаётся за Claude при работе с готовым файлом.
