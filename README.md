# ChatGrab — сборщик сообщений Telegram-чатов

Desktop-приложение для Windows, которое подключается к нескольким Telegram-чатам
(например, чатам-биржам, где поставщики и производители публикуют запросы и
предложения), собирает из них всю историю и новые сообщения по мере поступления,
и выгружает собранное в Excel (.xlsx) / JSONL / Markdown. Дальнейший разбор — какие товары
запрашивают, в каких объёмах, по какой цене — делает Claude в обычном чате при
работе с выгруженным файлом. Само приложение аналитику не делает: только надёжно
собирает и структурирует сырые данные.

## Возможности

- Один вход в Telegram на всё приложение (номер телефона → код → пароль
  двухэтапной проверки при необходимости).
- Список отслеживаемых чатов: добавление по ссылке/username или выбором из
  диалогов аккаунта, включение/выключение сбора по чату, удаление из списка
  с выбором «оставить данные» или «удалить вместе с чатом».
- Загрузка истории каждого чата с самого начала или от заданной даты, с
  докачкой при перезапуске — сбор продолжается с последнего собранного
  сообщения. Чаты грузятся по одному, а не параллельно — это специально:
  ограничение скорости у Telegram общее на аккаунт, и последовательная
  очередь реже вызывает `FloodWait`, чем параллельная загрузка.
- Прослушивание всех включённых чатов в реальном времени одновременно —
  это работает через push-события, а не опрос, поэтому общего лимита
  не касается и не требует очереди.
- Локальная база SQLite (один файл), дедупликация по паре (чат, id
  сообщения), обновление записи при редактировании исходного сообщения.
- Скачивание медиафайлов из сообщений — по умолчанию включены только фото
  (`photos/<chat_id>/<message_id>.jpg`), видео/голосовые/документы выключены.
  Каждый тип включается независимо на экране **Настройки → Какие
  медиафайлы скачивать** — например, для чатов, где важны видео или
  документы, а не только фото. Общий лимит размера файла (по умолчанию
  20 МБ) защищает от случайного скачивания слишком тяжёлых видео/документов
  — файлы больше лимита пропускаются, в базу пишется только их тип.
  Пути: `videos/<chat_id>/<message_id>.mp4`, `voice/<chat_id>/<message_id>.ogg`,
  `documents/<chat_id>/<message_id>_<имя файла>`.
- Экспорт: выбор чатов (объединить или по отдельности), формат Excel (.xlsx) /
  JSONL / Markdown-дайджест по дням, диапазон дат, три режима разбивки на
  файлы — «по размеру для Claude» (лимит токенов настраивается, по умолчанию
  180 000, токены считаются приближённо как символы/4 — без лишней
  зависимости), «по месяцам» или «одним куском». Инкрементальный экспорт
  («только новое с прошлой выгрузки»), журнал выгрузок с повтором прошлых,
  пресеты, архив медиафайлов рядом с выгрузкой, редактируемая шапка
  Markdown-дайджеста. Строки в выгрузке всегда идут строго по времени
  (от старых к новым), даже если объединяются несколько чатов сразу.
  Excel-выгрузка — по колонкам (дата и время, чат, автор, ник, текст с
  пометками ответа/пересылки, медиа) с кликабельными ссылками на файл,
  если он не упакован отдельно в zip.
- Экран **Обзор**: сводка по базе и плитки по каждому чату с графиком
  активности за 16 суток и предупреждениями (сбор выключен, чат в очереди,
  давно нет сообщений).
- Экран **Поиск в собранном**: полнотекстовый поиск (SQLite FTS5) с
  фильтрами по чату, автору, датам, медиа/пересылкам/ответам — чтобы
  проверять качество сбора, не открывая Telegram. Найденное можно сразу
  отправить на экспорт.
- Правила игнора (по автору или стоп-слову, глобально или по чату) —
  помечают сообщения скрытыми, не удаляя их; можно применить задним
  числом к уже собранному. Список авторов по чату — чтобы быстро находить
  спам.
- Адаптивная пауза между запросами истории (растёт после `FloodWait`,
  плавно снижается на успешной серии), расписание окна загрузки истории,
  проверка целостности с «залатать пропуски», устойчивость к обрыву сети.
- Резервные копии базы по расписанию, сжатие базы (VACUUM), быстрый доступ
  к папкам базы и медиафайлов.
- **Защита мастер-паролем** (Настройки → «Защита мастер-паролем»): файл входа
  в Telegram и ключ приложения (api_hash) шифруются на диске (PBKDF2 + Fernet/
  AES). Пароль нигде не хранится — при запуске приложение спрашивает его перед
  тем, как что-либо делать с Telegram. Пока приложение работает, файл входа
  временно расшифрован на диске (иначе Telethon не может с ним работать) и
  зашифровывается обратно при штатном закрытии программы; если забыть пароль —
  восстановить его нельзя, только сбросить защиту и войти в Telegram заново
  (ключи api_id/api_hash всегда можно посмотреть заново на my.telegram.org).
- **Конструктор Telegram-ботов** (экран **Боты**): создавайте и ведите несколько
  независимых ботов внутри того же приложения — та же база, тот же вход в
  Telegram, то же шифрование. Два типа:
  - **Бот-ассистент (Bot API)** — токен от @BotFather, принимает личные
    сообщения, ведёт диалог по сценарию (FSM, шаги хранятся декларативно —
    редактируются в UI без кода), сохраняет заявку и пересылает менеджеру.
  - **Юзербот-триггеры** — использует уже выполненный вход текущего
    аккаунта (вторая сессия не поднимается): слушает чат по ключевым
    словам/фильтрам и отвечает в личку по шаблону. Троттлинг, cooldown
    между исходящими и обработка `FloodWait` — как в основном парсере.

  Экраны: **Боты** (список, старт/стоп), **Заявки** (мини-трекер со
  статусом и переназначением), **Правила** (триггер → действия),
  **Сценарии** (пошаговый редактор вопросов), **Шаблоны** (сообщения с
  `{переменными}`), **Тест** (прогон правила или сценария без реальной
  отправки), **Журнал** (сработавшие триггеры, ошибки, отправленные
  сообщения), **Аналитика** (рейтинг контактов по частоте+давности активности,
  воронка по заявкам, экспорт заявок в Excel). Пресеты **B2B**/**B2C**/**Кастом**
  задают стартовый сценарий и правила при создании бота — дальше всё
  редактируется как обычные записи. Токены Bot API шифруются так же и на
  тех же условиях, что и api_hash (см. выше) — включая переход между
  включённой/выключенной защитой мастер-паролем, не только их первое сохранение.

## Установка

### Вариант 1 — готовый файл (рекомендуется)

Каждый пуш в этот репозиторий собирает portable `ChatGrab.exe` в GitHub
Actions (`.github/workflows/build-windows.yml`, раннер `windows-latest`,
PyInstaller). Скачайте его со вкладки **Actions → последний прогон →
Artifacts → ChatGrab-windows**, либо, если в репозитории есть релиз с тегом
`vX.Y.Z`, — со страницы **Releases**.

`ChatGrab.exe` не требует установки — запускается двойным щелчком. Все
данные (база, фото, выгрузки, файл входа, `config.json`) приложение хранит
в папке рядом с собой, поэтому всю папку с `.exe` можно свободно переносить
на другой компьютер или флешку вместе с уже собранными данными.

### Вариант 2 — запуск из исходников

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Требуется Python 3.11+.

### Вариант 3 — собрать .exe самостоятельно

На Windows, после `pip install -r requirements.txt pyinstaller`:

```
pyinstaller packaging/chatgrab.spec --noconfirm --clean
```

Готовый файл появится в `dist\ChatGrab.exe`.

## Безопасность и приватность — что важно понимать

- **Защита мастер-паролем не включена по умолчанию.** Пока вы не включите
  её в Настройках, `api_hash` и файл входа в Telegram хранятся на диске
  открытым текстом — это осознанный компромисс (без пароля приложение проще
  запустить и восстановить), но включить защиту сразу после первого входа
  стоит на любой машине, к которой есть доступ у кого-то ещё.
- **Файл входа — это, по сути, ключ от аккаунта**, эквивалент пароля: у кого
  есть файл `worker.session`, тот может войти в аккаунт без 2FA и без кода
  подтверждения, с любого устройства. Шифрование мастер-паролем защищает
  его только пока приложение закрыто — во время работы файл лежит
  расшифрованным (иначе Telethon не может его открыть), поэтому доступ к
  запущенной машине эквивалентен доступу к аккаунту. Относитесь к этому
  файлу и к `config.json` так же, как к паролю, — не пересылайте, не
  кладите в облачную синхронизацию без шифрования диска.
- **Сама база `chatgrab.db` не шифруется.** В ней открытым текстом хранятся
  собранные сообщения, имена и юзернеймы участников чужих чатов, контакты и
  заявки конструктора ботов — то есть личные данные третьих лиц, а не
  только ваши собственные секреты. Шифрование мастер-паролем на неё не
  распространяется (это шифрование сессии/токенов, не архива сообщений).
  Учитывайте это при выборе, где хранить и с кем делиться папкой с данными.
- **Portable-режим требует папки с правом записи.** Не запускайте
  `ChatGrab.exe` из `C:\Program Files\…` — без прав администратора
  приложение не сможет создать рядом папку `data\` и `config.json`.
  Desktop, Documents или любая своя папка пользователя подходят.
- **Зависимости стоит периодически проверять** (`pip-audit` или аналог) —
  Telethon, aiogram, cryptography, openpyxl и PySide6 обновляются, в них
  бывают исправления безопасности; версии закреплены в `requirements.txt`
  намеренно (воспроизводимая сборка), но это значит, что обновлять их
  нужно руками, а не полагаться на «подтянется само».

## Первый запуск

1. **Ключи доступа.** На <https://my.telegram.org> → «API development tools»
   создайте приложение и получите `api_id` и `api_hash`. Внесите их на
   экране **Настройки → Доступ к Telegram** и нажмите «Сохранить».
2. **Отдельный аккаунт.** Файл входа даёт полный доступ к аккаунту Telegram
   — для сбора рекомендуется завести отдельный номер, не основной личный,
   а не использовать основной аккаунт.
3. **Вход.** Экран **Подключение** → введите номер телефона → код из
   Telegram → пароль двухэтапной проверки, если он включён в аккаунте.
   Вход выполняется один раз на всё приложение.
4. **Добавьте чаты.** Экран **Чаты → Добавить чат** — ссылкой/username или
   выбором из своих диалогов. По умолчанию каждый чат грузит всю историю
   с начала; глубину («вся история» или «с такой-то даты») можно задать
   отдельно для каждого чата при добавлении.
5. **Дождитесь сбора** (экран **Сбор данных** или **Обзор**) — чаты
   грузятся по очереди, это нормально при нескольких чатах сразу.
6. **Экспортируйте** — экран **Экспорт**: выберите чаты, формат и период,
   нажмите «Экспортировать». Получившийся файл можно приложить прямо в
   чат с Claude для разбора запросов, объёмов и цен.
7. **(Необязательно) Заведите бота** — экран **Боты → Новый бот**: юзерботу
   нужен уже выполненный вход (см. пункт 3), бот-ассистенту — токен от
   @BotFather. Пресет B2B/B2C сразу даёт рабочий сценарий и правило; кастом
   собирается вручную на вкладках «Правила» и «Сценарии».

## Где что лежит

Рядом с `ChatGrab.exe` (или, при запуске из исходников, в корне проекта)
приложение создаёт:

```
config.json              — api_id/api_hash и пути (не в коде, отдельно)
data/chatgrab.db          — база данных (сообщения, чаты, настройки, пресеты)
data/photos/<id>/…        — скачанные фото, по чатам (включено по умолчанию)
data/videos/<id>/…        — скачанные видео, по чатам (выключено по умолчанию)
data/voice/<id>/…         — скачанные голосовые, по чатам (выключено по умолчанию)
data/documents/<id>/…     — скачанные документы, по чатам (выключено по умолчанию)
data/exports/             — выгруженные файлы по умолчанию
data/session/             — файл входа в Telegram-аккаунт
data/backups/             — резервные копии базы
```

Боты, правила, сценарии, заявки и контакты конструктора ботов хранятся в
той же `data/chatgrab.db` — отдельной базы или папки под них нет. Выгрузка
заявок в Excel (экран **Боты → Заявки**) сохраняется в тот же `data/exports/`.

Файл входа (`data/session/worker.session`) и `config.json` — храните
локально, никогда не пересылайте и не кладите в выгрузки: они дают полный
доступ к аккаунту Telegram. Если включена защита мастер-паролем, вместо
`worker.session` на диске (пока приложение закрыто) лежит зашифрованный
`worker.session.enc`, а `api_hash` в `config.json` не хранится в открытом
виде вовсе.

## Ограничения

Приложение не извлекает товары, объёмы и цены из текста и не строит
сводки — только надёжно собирает и выгружает сырые данные. Разбор смысла
сообщений остаётся за Claude при работе с готовым файлом.

Конструктор ботов — минимальный тикет-трекер по заявкам, не полноценная
CRM: без маршрутизации по загрузке менеджеров, A/B-шаблонов, рабочих часов
и вебхуков во внешние системы (amoCRM, Bitrix24, Google Sheets) — модель
данных это допускает, но в текущей версии не реализовано. Массовая рассылка
в личку от юзербота ограничена троттлингом и cooldown'ом по каждому
контакту — это защита от блокировки аккаунта Telegram, а не настраиваемый
маркетинговый инструмент.
