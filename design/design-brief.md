# Промпт для Claude Code: перенос дизайна «Плотный рефреш» в TGchatGrab

Ты работаешь в репозитории **jataken/TGchatGrab** — десктопное приложение на **Python 3 + PySide6 (Qt Widgets)**, интерфейс на русском. Твоя задача: **переписать интерфейс приложения точно по приложенному HTML-макету**, сохранив всю существующую логику сбора данных, ботов и экспорта.

## 0. Что в архиве и как это читать

| Файл | Что это |
| --- | --- |
| `Обновлённый интерфейс 1a.dc.html` | **Целевой дизайн.** Все восемь разделов приложения в финальном виде. Это эталон — повторяй его. |
| `Текущий UI.dc.html` | Пересборка того, как приложение выглядит **сейчас** (из `theme.py`, `main_window.py`, `screens/*`). Нужна только для сравнения «до/после». |
| `Варианты дизайна.dc.html` | Три направления, из которых выбрано `1a`. Варианты `1b` и `1c` **не реализуем**. |

HTML-файлы — **дизайн-референс, а не код для копирования**. Реализация должна быть на PySide6 + QSS в существующей структуре `chatgrab/ui/`. Открой HTML в браузере и сверяйся с ним визуально: цвета, отступы, размеры шрифтов, порядок элементов, состояния наведения.

Фиделити: **высокое (hi-fi)**. Цвета, размеры и типографика финальные — воспроизводить попиксельно, не «примерно похоже».

**Данные в макете вымышленные** (закупки косметического сырья: «Сырьё для косметики — B2B», «глицерин 99.5% USP» и т. п.). Это только наполнение для демонстрации. Каждый элемент макета в §4 сопоставлен с реальным источником данных в коде — **все числа, подписи, статусы и строки журнала должны приходить из БД и коллектора, ничего не хардкодить**. Если данных нет — используй правила пустых состояний из §7.

## 1. Что менять и что не трогать

**Меняем только слой представления:**
- `chatgrab/ui/theme.py` — расширить палитру и QSS,
- `chatgrab/ui/main_window.py` — сайдбар,
- `chatgrab/ui/widgets.py` — общие виджеты + новые,
- `chatgrab/ui/screens/*.py` и `chatgrab/ui/screens/bots/*.py` — верстка экранов.

**Не трогаем** (ни сигнатуры, ни поведение): `chatgrab/db/*`, `chatgrab/telegram/*`, `chatgrab/services/*`, `chatgrab/bots/*` (кроме случаев, когда для отображения нужен новый **read-only** запрос — тогда добавляй метод в `db/database.py`, не меняя существующие).

Все существующие сигналы и таймеры сохраняются: `collector.chats_changed`, `collector.stats_changed`, `collector.log_event`, `bot_manager.bots_changed`, периодические `QTimer` на экранах. Экраны по-прежнему создаются в `MainWindow.__init__` и получают `(ctx, navigate)`, метод `on_show(**kwargs)` сохраняется — навигация `navigate("collect", chat_id=...)` и `navigate("export", search_filters=...)` должна продолжать работать.

## 4. Экраны: элементы и источники данных

Ниже для каждого элемента указано, **откуда брать реальные данные**. `db = ctx.db`, `cfg = ctx.config`, `col = ctx.collector`.

### 4.1 Обзор (`screens/overview.py`)
- Заголовок «Обзор сбора».
- Строка состояния под ним: точка ACCENT_400 с пульсацией + текст. Если есть чат `loading`: `Грузится «{title}», остальные ждут в очереди — лимит Telegram общий на аккаунт`. Иначе: `Вся история собрана, приложение только слушает новые сообщения`. Точка показывается только в первом случае.
- Справа две кнопки: «Приостановить всё» (вторичная) — ставит на паузу загрузку истории по всем чатам через `col.toggle_history_loading` для активных; «＋ Добавить чат» (основная) — открывает тот же `AddChatDialog`, что и экран «Чаты».
- **Панель метрик, 5 ячеек** (§3.7):
  1. `СООБЩЕНИЙ В БАЗЕ` = `sum(db.message_count(c["chat_id"]) for c in chats)`
  2. `МЕДИАФАЙЛОВ` = `sum(db.media_count(...))`
  3. `ЧАТОВ В РАБОТЕ` = `f"{enabled_n}"` + серым `f" / {len(chats)}"`
  4. `РАЗМЕР БАЗЫ` = `db.file_size() / 1024**2`, формат `613.4` + серым ` МБ`
  5. `ПРОШЛАЯ ВЫГРУЗКА` = `db.list_export_log(limit=1)[0]["created_at"]` в формате `19.08` + серым ` 14:02`; если пусто — `ещё не было`.
  Числа — с разделителем-пробелом (как сейчас: `f"{n:,}".replace(",", " ")`).
- Кикер `ЧАТЫ В РАБОТЕ` + затухающая вправо линия (`linear-gradient(90deg, DIVIDER, transparent)`, высота 1px).
- **Сетка плиток**: 3 колонки при ширине контента ≥ 960px, зазор 12px (существующая логика `cols = width // 320` сохраняется как fallback для узкого окна). Одна плитка = один чат из `db.list_chats()`, порядок как возвращает БД.
- **Плитка чата** (карточка §3.8, курсор-палец, клик → `navigate("collect", chat_id=...)`):
  - левая полоса статуса (для `loading` полная непрозрачность, для остальных 75%);

## 5. Анимации (обязательная часть дизайна)

Все реализуются на Qt-средствах: `QPropertyAnimation`, `QVariantAnimation`, `QTimer` + перерисовка в `paintEvent`. Ничего не должно «дёргаться» при периодическом `refresh()` — анимации привязаны к событиям, а не к тикам таймера.

| Что | Как | Длительность / кривая |
| --- | --- | --- |
| Пульсация точки статуса | opacity 1→0.35 и масштаб 1→0.82 и обратно, бесконечно | 1.7 с, `InOutSine` |
| Гало точки подключения | расширяющееся кольцо 0→9px, opacity 0.45→0 | 2.2 с, `OutQuad`, бесконечно |
| Бегущий блик на прогрессе | светлая полоса шириной 26–30% от дорожки едет слева направо | 2.4–2.6 с, линейно, бесконечно, **только при активной загрузке** |
| Рост столбиков спарклайна | scaleY 0.15→1 от нижней кромки, задержка `i × 16 мс` | 500 мс, `OutCubic`, при показе/смене чата |

## 7. Пустые, загрузочные и ошибочные состояния

- **Нет чатов**: на Обзоре вместо сетки — пунктирная карточка на всю ширину контента с текстом `Пока нет отслеживаемых чатов — добавьте первый, и приложение начнёт собирать историю` и основной кнопкой `＋ Добавить чат`. Панель метрик показывается с нулями.
- **Нет сообщений в чате**: в плитке вместо числа `—`, спарклайн не рисуется (оставить пустое место той же высоты, чтобы плитки не «прыгали»).
- **Ничего не найдено** в поиске: карточка-заглушка (пунктирная рамка) с текстом `Ничего не найдено — попробуйте другой запрос или снимите фильтры` и ghost-кнопкой `Сбросить`.
- **Нет ботов**: только пунктирная карточка создания.
- **Не авторизован**: сайдбар — точка BAD и `Нет подключения`; на Обзоре плашка WARN `Аккаунт не подключён — сбор остановлен` со ссылкой на «Подключение».
- **Не заданы api_id/api_hash**: на «Подключении» — существующий текст-ошибка + кнопка `Перейти в настройки`.
- **Загрузка данных для UI** (список диалогов Telegram и т. п.): вместо содержимого — 3 скелетон-строки: блок радиусом 8, фон `rgba(233,233,237,8)`, по нему бегущий блик 1.6 с.
- **Ошибка чата** (`last_error`): полоса и плашка статуса красные, строка предупреждения BAD_FG, в быстрых действиях первая кнопка — `Повторить`.
- Все тексты ошибок Telegram по-прежнему проходят через `telegram/errors.humanize_error`.

## 8. Безопасность вывода (не потерять при переверстке)

В текущем коде это явно продумано — сохрани:
- любой текст из Telegram (название чата, имя автора, текст сообщения, `last_error`, имя бота) выводится с `setTextFormat(Qt.PlainText)`;
- жирность/цвет задаются через QSS или свойства виджета, **никогда не через HTML-обёртки в f-строках**;
- пути к файлам открываются через `QDesktopServices.openUrl(QUrl.fromLocalFile(...))`;
- все `QAbstractItemView`/`QDialog`/`QScrollArea` получают явные тёмные фон и цвет текста (в текущем `build_qss` есть комментарии, почему — не удаляй эти правила, а перенеси в новый QSS).

## 9. Порядок работы

1. Прочитай `chatgrab/ui/theme.py`, `main_window.py`, `widgets.py` и все `screens/*.py` — дизайн не меняет логику, только представление.
2. Расширь `theme.py`: новые константы (§2) + переписанный `build_qss()`.

4. Перепиши сайдбар (§3.1), включая иконки из макета в `resources/icons/`.
5. Экраны по одному в порядке §4.1 → §4.8. После каждого — запусти приложение и сравни со соответствующим разделом HTML-макета (в макете переключение по сайдбару работает).
6. Проверь: пустые состояния (§7), переключение всех восьми разделов, все тумблеры и чекбоксы, экспорт с пересчётом оценки, все восемь вкладок ботов, окно 980×620 (минимальный размер из `main_window.py`) — на нём сетка плиток должна перестраиваться в 2 и 1 колонку, панели метрик переносить ячейки, а не обрезаться.
